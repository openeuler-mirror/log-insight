# 规则表项设计说明

> 对应代码：`backend/app/models/rule.py`（模型）、`backend/app/api/rules.py`（接口与校验）、
> `backend/app/modules/diagnosis/rule_engine.py`（匹配引擎）。
> 迁移版本：Alembic 基线 `0001`。

## 一、设计定位

规则是**平台级全局配置**（无 `team_id`，不区分团队），由具备 `rule:manage` 权限的用户维护，
Worker 每个任务执行时从数据库加载一次启用规则，实现**免重启热加载**。

三条设计主线：

1. **内容版本**：`version` 是**单条规则自己的内容版本**，仅当内容字段（名称/描述/匹配类型/匹配内容/阈值/脚本/级别/适用范围/优先级）真正变化时才 +1；
   单纯启停或提交内容未变的 PUT 都不产生新版本。它只作展示与审计参考，**不承担热加载通知职责**（热加载靠每任务重新查库）。
2. **类型分派**：用 `match_type` 区分「日志行匹配（正则/关键字）」与「指标阈值匹配」两条不同匹配通路。
3. **可审计**：所有变更写入独立的 `rule_audit_logs` 表，保留变更前后明细。

## 二、主表 `rules` 字段清单

| 字段 | 类型 | 默认值 / 约束 | 说明 |
|------|------|---------------|------|
| `id` | Integer | 主键，自增 | 规则 ID |
| `name` | String(128) | 非空，**建索引** | 规则名称；平台与各团队作用域内按名称区分（团队规则同名覆盖通用规则） |
| `description` | String(512) | 默认 `""` | 规则说明 |
| `match_type` | Enum(`MatchType`) | 非空 | 匹配类型：`regex` / `keyword` / `threshold` |
| `pattern` | Text | 默认 `""` | 匹配内容：正则表达式 或 关键字（`threshold` 类型时为空） |
| `threshold` | JSONB | 默认 `{}` | 阈值定义，结构见下文「四」 |
| `severity` | Enum(`Severity`) | 默认 `warn` | 告警级别：`info` / `warn` / `error` / `critical` |
| `log_type` | String(64) | 默认 `""` | 适用日志类型，**空串表示全部适用** |
| `server_type` | String(64) | 默认 `""` | 适用服务器类型，**空串表示全部适用** |
| `enabled` | Boolean | 默认 `true` | 是否启用；停用后引擎加载时直接过滤 |
| `priority` | Integer | 默认 `100` | 优先级，**数值越小越靠前**（列表按 `priority, id` 排序） |
| `version` | Integer | 默认 `1`，**建索引** | 本条规则的内容版本；仅内容变更时 +1，启停不变 |
| `is_builtin` | Boolean | 默认 `false` | 是否内置预置规则（标记来源）；不限制删除，前端删除时额外提示 |
| `created_by` | Integer | 外键 → `users.id`，可空 | 创建人；内置规则为 `NULL` |
| `created_at` | DateTime(tz) | `now()` 服务端默认 | 创建时间 |
| `updated_at` | DateTime(tz) | `now()`，更新时自动刷新 | 更新时间 |

**表级约束**

无表级唯一约束。规则身份按「作用域 + `name`」区分：同一作用域（平台或某个团队）内不应出现同名规则，
跨作用域允许同名（团队规则按名称覆盖平台通用规则）。

> 历史说明：早期模型上有 `UNIQUE (name, version)`（`uq_rule_name_version`），是「每次保存插入新行」那版
> 版本化存储设计的遗留物；改为原地更新后它已无意义，且会阻碍团队规则与通用规则同名，故已移除。

## 三、枚举取值

**`MatchType`（匹配类型）**

| 值 | 含义 | 匹配对象 |
|----|------|---------|
| `regex` | 正则匹配日志行 | 日志条目 `entry.raw`，`re.search` |
| `keyword` | 关键字包含 | 日志条目 `entry.raw`，`in` 判断 |
| `threshold` | 指标阈值 | 性能指标点 `metric_points` |

**`Severity`（告警级别）与健康评分权重**

| 值 | 权重 | 说明 |
|----|------|------|
| `info` | 1 | 提示 |
| `warn` | 3 | 警告 |
| `error` | 7 | 错误 |
| `critical` | 10 | 严重 |

健康评分公式：`health_score = max(0, 100 - Σ(命中规则权重))`（上限扣 100 分）。

## 四、`threshold` 字段结构（JSONB）

仅当 `match_type = threshold` 时使用，必须包含 `metric` / `op` / `value` 三个键：

```json
{
  "metric": "cpu.usage",
  "op": ">",
  "value": 90
}
```

| 键 | 类型 | 说明 |
|----|------|------|
| `metric` | String | 指标名，如 `cpu.usage` / `mem.used_pct` |
| `op` | String | 比较符，仅允许 `>` `<` `>=` `<=` `==` |
| `value` | Number | 比较阈值 |

匹配逻辑：遍历任务解析出的指标点，`metric_name` 相符且 `value op 阈值` 成立即命中。

## 五、审计表 `rule_audit_logs` 字段清单

| 字段 | 类型 | 默认值 / 约束 | 说明 |
|------|------|---------------|------|
| `id` | Integer | 主键，自增 | 审计记录 ID |
| `rule_id` | Integer | 外键 → `rules.id`，`ON DELETE CASCADE`，**建索引** | 关联规则 |
| `rule_name` | String(128) | 非空 | 冗余规则名（规则删除后仍可追溯） |
| `action` | String(16) | 非空 | 动作：`create` / `update` / `delete` |
| `operator_id` | Integer | 外键 → `users.id` | 操作人 |
| `detail` | JSONB | 默认 `{}` | 变更明细：新增存全量，修改存 `{old, new}` |
| `created_at` | DateTime(tz) | `now()` 服务端默认 | 操作时间 |

## 六、接口层校验规则

`POST /api/rules`、`PUT /api/rules/{id}` 保存前统一调用 `validate_rule()`：

| 匹配类型 | 校验要求 |
|---------|---------|
| `regex` | `pattern` 非空；非法正则语法报 400；命中灾难性回溯黑名单（括号内含 `+` 的嵌套量词 `(...+...)`、畸形量词 `{m,,n}`）报 400 |
| `keyword` | `pattern` 非空 |
| `threshold` | `threshold` 必须包含 `metric` / `op` / `value` 三个键 |

其他接口约束：

- 增 / 改 / 删均要求当前用户拥有 `rule:manage` 权限，否则 403；
- 创建时 `version = 1`；更新时逐字段比对**内容字段**（不含 `enabled`），真有变化才 `version += 1`
  （即：启停、以及内容完全相同的 PUT 都不产生新版本）；
- 内置规则（`is_builtin=true`）同样可被 `rule:manage` 权限者删除（前端删除前二次确认并提示需手动重建）；
  若开启 `SEED_DEMO_DATA`，重启后会按 `name` 重新写入该内置规则。

## 七、请求 / 响应模型字段

`RuleCreate` / `RuleUpdate`（写入）：`name, description, match_type, pattern, threshold,
severity, log_type, server_type, enabled, priority`。

`RuleInfo`（读出，= Create + 以下只读字段）：`id, version, is_builtin, created_by,
created_at, updated_at`。

## 八、内置预置规则（演示种子数据）

由 `backend/app/main.py::seed_builtin_rules()` 幂等写入，按 `name` 判重；均带 `is_builtin=true`
（仅为标记来源，`rule:manage` 权限者可停用或删除）：

| 名称 | 匹配类型 | `pattern` / `threshold` | 级别 | `log_type` | `priority` |
|------|---------|------------------------|------|-----------|-----------|
| OOM 内存溢出 | keyword | `Out of memory` | critical | syslog | 10 |
| 磁盘 IO 错误 | regex | `(?:I/O error\|Buffer I/O error\|blk_update_request)` | error | syslog | 20 |
| CPU 使用率过高 | threshold | `{metric: cpu.usage, op: ">", value: 90}` | warn | `""`（全部） | 30 |
| 服务启动失败 | keyword | `Failed with result` | error | syslog | 40 |

> 注：内置规则的 `created_by` 为 `NULL`，`version` 为初始值 `1`（内容未改过就不会增长）。
